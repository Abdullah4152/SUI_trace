# Step Utility Interventions for Reasoning Traces

## Repository map

```
config/
  sui_final_config.json            Dataset paths, model IDs, decoding settings and thresholds
scripts/
  prepare_pilot_sample.py          Benchmark sampling
  run_pilot_generation.py          Reasoning-trace generation
  run_pilot_interventions.py       Step-level interventions (SUI)
  summarize_pilot.py               SUI utility summary
  prepare_uatr_jobs.py             High-risk step selection
  run_uatr_experiment.py           UATR revision and baselines
  summarize_uatr_experiment.py     Revision summary
  pilot_lib.py                     Shared segmentation, scoring and API helpers
human_validation/                  Rater annotations, protocol and agreement analysis
docs/                              Runbook, data card and anonymization notes
README.md                          Setup and step-by-step run guide
```

This repository is the reproducibility artifact for *When Do Reasoning Traces Matter? Step-Level Utility Interventions for Open Reasoning Models*. It implements **Step Utility Interventions (SUI)**, which audit the contribution of individual reasoning steps, and **Utility-Aware Targeted Revision (UATR)**, which revises the high-risk steps selected from SUI signals. All model identifiers and settings live in `config/sui_final_config.json`; change them there rather than in the scripts.

| Role | Models and benchmarks |
|---|---|
| Target reasoning models | [GLM-5.1](https://huggingface.co/zai-org/GLM-5.1), [Nemotron-3 Nano Omni 30B Reasoning](https://huggingface.co/nvidia/Nemotron-3-Nano-Omni-30B-A3B-Reasoning-BF16), [Mistral Medium 3.5 128B](https://huggingface.co/mistralai/Mistral-Medium-3.5-128B) |
| Intervention editor | Qwen2.5-72B-Instruct |
| Judge | Llama-3.1-70B-Instruct |
| Source benchmarks | MATH-500, GPQA Diamond, LogiQA 2.0 |

The repository ships code, configuration and human annotations only. Generated outputs—benchmark samples, reasoning traces, intervention records, utility scores, revision results and paper tables—are excluded from the source tree; every quantitative result is produced by running the pipeline below. The human annotations in `human_validation/` are the one component that cannot be regenerated by running code.

## 1. Prepare the Environment

The scripts call NVIDIA-hosted model endpoints. To clone from the terminal, install [GitHub CLI](https://cli.github.com/) if needed and authenticate once:

```bash
gh auth login
gh auth status
export ANONYMOUS_REPOSITORY_URL=https://github.com/OWNER/REPOSITORY.git
```

Run commands from the repository root.

```bash
git clone "$ANONYMOUS_REPOSITORY_URL" sui_trace
cd sui_trace
python3 --version
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Use Python 3.10 or newer. On Windows PowerShell, activate the environment with `.\.venv\Scripts\Activate.ps1`; if Windows exposes the Python launcher instead of `python`, use `py -m venv .venv`. Do not install packages globally on a shared server.

## 2. Install the Benchmarks Locally

Download the three source benchmarks from their official releases: [MATH-500](https://huggingface.co/datasets/HuggingFaceH4/MATH-500), [GPQA Diamond](https://github.com/idavidrein/gpqa) and [LogiQA 2.0](https://github.com/csitfun/LogiQA2.0). Then point `dataset_paths` in `config/sui_final_config.json` at your local copies:

```json
"dataset_paths": {
  "math": "/path/to/MATH-500/train-00000-of-00001-7320a6f3aba8ebd2.parquet",
  "gpqa_diamond": "/path/to/GPQA-Diamond/gpqa_diamond.csv",
  "logiqa_test": "/path/to/LogiQA-2.0/test.jsonl"
}
```

The sampler draws 30 instances per benchmark (`pilot.instances_per_benchmark`) under seed 20260509, stratified by level and type for MATH-500, by domain for GPQA Diamond and by label for LogiQA 2.0. Expected count: 90 instances in total.

Store each API key outside the repository. The pipeline reads up to eight independent keys so that workers can run in parallel without sharing rate limits:

```bash
export NVIDIA_API_KEY_1=...
export NVIDIA_API_KEY_2=...
# ... through NVIDIA_API_KEY_8
```

Use `--workers N`, where `N` is the number of keys you supplied, and edit `api_key_env_names` in the config if you supply fewer than eight.

## 3. Run the SUI Audit

All stages write into the output directory you pass; `outputs/` is git-ignored.

### Build the benchmark sample

```bash
python scripts/prepare_pilot_sample.py --config config/sui_final_config.json --out-dir outputs/sui
```

### Generate reasoning traces

```bash
python scripts/run_pilot_generation.py --config config/sui_final_config.json --instances outputs/sui/pilot_instances.jsonl --out-dir outputs/sui --workers 8
```

### Run step-level interventions

This stage edits individual reasoning steps and measures answer, correctness and continuation change. It is the longest stage and is resumable: re-running it continues from existing outputs, and `--fresh` starts over.

```bash
python scripts/run_pilot_interventions.py --config config/sui_final_config.json --instances outputs/sui/pilot_instances.jsonl --traces outputs/sui/pilot_trace_metadata.jsonl --out-dir outputs/sui --workers 8
```

To check progress mid-run:

```bash
python scripts/report_resume_status.py --config config/sui_final_config.json --instances outputs/sui/pilot_instances.jsonl --traces outputs/sui/pilot_trace_metadata.jsonl --out-dir outputs/sui
```

### Compute SUI utility scores

```bash
python scripts/summarize_pilot.py --out-dir outputs/sui
```

Utility rows are written to `outputs/sui/pilot_utility_scores.csv` and the summary to `outputs/sui/pilot_summary.md`.

## 4. Run UATR Revision

### Select high-risk steps

```bash
python scripts/prepare_uatr_jobs.py --sui-dir outputs/sui --out-dir outputs/uatr
```

Job selection uses seed 20260515. `--max-jobs` and `--max-per-model-benchmark` can shrink the job set and make it less balanced across models than the SUI audit it came from.

### Run UATR and baselines

UATR runs alongside the original-trace, random-step, self-refine, debate and self-consistency baselines.

```bash
python scripts/run_uatr_experiment.py --config config/sui_final_config.json --sui-dir outputs/sui --jobs outputs/uatr/uatr_jobs.jsonl --out-dir outputs/uatr --workers 8
```

### Compute revision results

```bash
python scripts/summarize_uatr_experiment.py --out-dir outputs/uatr
```

Before comparing methods, check how many jobs completed and report the per-method row count and the model/benchmark breakdown alongside any comparison.

## 5. Metric Settings

Use these definitions and preserve each metric's denominator:

- **Δans, answer change:** 1 if the edited continuation produced a complete answer that differs from the baseline answer, otherwise 0.
- **Δcorr, correctness change:** 1 if the edited continuation produced a complete answer whose correctness differs from the baseline, otherwise 0.
- **Δcont, continuation divergence:** 1 − BERTScore F1 between the edited and baseline continuations, clipped to [0, 1].
- **Utility score:** Δans + Δcorr + Δcont, computed only for edits that pass validity checks (`valid_for_utility`). An edit is valid when it changes the step (semantic similarity < 0.95, lexical overlap < 0.90), keeps 0.4–1.8× the original length, introduces no new answer leakage or meta-commentary and does not target the final-answer step.
- **Step bin:** `decision-critical` if Δans or Δcorr is 1; `supportive` if Δcont > 0.70; otherwise `redundant`. Invalid edits are `invalid-edit`. This is an automatic analysis variable, not ground truth.
- **Revision correctness:** scored strictly—a missing or unparsed final answer counts as incorrect. State whether any accuracy uses all rows or parsed rows only.

## 6. Aggregate Statistics


This writes confidence intervals and pairwise tests to `outputs/statistics/confidence_intervals_and_tests.md`.

## 7. Reproduce the Human Validation Analysis

This analysis runs without API keys and without a pipeline rerun, because the annotations are included. Three independent raters, anonymized as `R1`, `R2` and `R3`, annotated a calibration split and then a main split. See `human_validation/HUMAN_VALIDATION_INSTRUCTIONS.md` for the protocol, rating scales and reliability targets.

### Main split

Used for all reported agreement figures:

```bash
python human_validation/analyze_human_annotations.py --annotations human_validation/human_validation_annotation_sheet_filled.csv --out-dir outputs/human_validation_main --split main
```

### Calibration split

Used only to describe the calibration phase:

```bash
python human_validation/analyze_human_annotations.py --annotations human_validation/human_validation_annotation_sheet_filled.csv --out-dir outputs/human_validation_calibration --split calibration
```

### Rebuild the annotation sample

This produces a *new* sample from a fresh SUI run, not the one the raters annotated:

```bash
python human_validation/make_human_validation_sample.py --sui-dir outputs/sui --out-dir outputs/human_validation_sample
```

## 8. Reproducibility Notes

- **Expect drift.** The target, editor and judge models are hosted services. Reruns will not reproduce outputs token-for-token, and derived rates will move. Sampling seeds are fixed where the pipeline controls them.
- **Scale matters.** The intervention and revision stages operate on different numbers of rows; a revision comparison on a small job set has wide confidence intervals.
- **Cost.** The intervention stage issues a model call per sampled step, and self-consistency issues several calls per instance. Use `--limit` and `--dry-run` to size a run before committing to it.
- **Runtime.** The configuration uses an 1800-second request timeout, two retries per transient failure and a 30-second cooldown after each successful response.
- **Local smoke test.** `scripts/smoke_test_local.py` exercises trace segmentation and scoring without API access.
